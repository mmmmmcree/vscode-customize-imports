# Dark 2026 + One Dark Pro

Dark 2026 界面与 One Dark Pro 完整的语法、语义高亮配色，附带 Synthwave 光晕。

C++ 使用明亮雾蓝显示命名空间、黄色显示类和结构体名称、薄荷绿显示 concept 名称；枚举类型名为柔玫粉，与命名空间区分，枚举成员为荧光绿 `#7CFF6B`，与 `#include` 文件名的字符串绿、青色的 `void`／`bool` 和橙色的宏区分。`enum class MyClass` 中单独区分的是 `MyClass`，`enum`、`class`、`struct`、`constexpr`／`consteval`／`constinit`／`static_assert` 等关键字沿用 One Dark Pro 的紫色。类型查询、转换及基础类型为青色。完整分组见[配色说明](Dark2026-OneDarkPro.md)。C++ 规则独立维护在 `languages/cpp.json`，随主题构建合并，无需单独安装语言配色插件。

cpptools 1.35.6 的通用 `type` 分类会让枚举类型名与普通类名同色；仅添加 `enum:cpp` 主题规则不足以解决。扩展现在为显式枚举类型名提供稳定的补充前景色，并调用语言服务的符号高亮取得同文件引用：例如 `enum class DrainDirection` 中的 `DrainDirection` 及本文件引用使用柔玫粉，`class DrainView` 中的 `DrainView` 保留黄色。`enum`、`class` 关键字不涂成类型色，不按同名字符串全局替换。原生服务提供独立 `enum` 分类时自动交给原生语义高亮；可用 `dark2026OneDarkPro.cppEnumTypeHighlighting` 关闭补充层，不需要 Loader。

枚举补充层覆盖当前文件里的声明、前向声明、`using enum` 等显式枚举入口及语言服务返回的同文件符号范围。没有显式枚举入口的其他文件中引用，继续由语言服务配色；不扫描整个工作区或把所有通用类型改成枚举色。

附带语法规则补充 concept 声明、复合约束中的 `noexcept` 和模块 `import`。Concept 优先使用当前语言服务的原生 `concept` 语义分类：通过 VS Code 的公开命令查询 token legend，支持时不添加装饰、不查询定义，也不注册会替换 C++ 语言服务的语义提供器。

本机 `ms-vscode.cpptools` 1.35.6 的语义 token 没有独立的 `concept` 分类，因此仍需补充薄荷绿着色。补充层通过 cpptools 的“转到定义”确认模板约束、concept 表达式及受约束 `auto` 中的名字，覆盖 `template <dispatch_source_c Inputs, typename Router>`、函数体内的 `if constexpr (deque_c<Queue>)`、`requires queue_c<T>`、复合约束与其他 concept 定义；支持限定名和定义位于其他头文件。已确认范围随编辑移动，异步复核期间保持颜色，临时空结果不清除；复核完成后合并更新，相同范围不重复绘制，滚动后保留已确认范围。改名、删除定义或确认目标是普通类时会撤销旧色。`typename` 和普通的非类型模板参数保持各自配色。

此补充层仍是编辑器装饰，不是 cpptools 新增的原生语义分类；首次确认仍需等待语言服务。普通类模板、函数模板和变量模板也可能成为候选，但定义未确认为 concept 时不改变其颜色，不按 `_c` 后缀猜测。若只希望使用原生配色，设置 `"dark2026OneDarkPro.cppConceptHighlighting": false`，无需 Loader。提供 `concept` 分类的语言服务会通过主题原生语义规则显示薄荷绿。

模板签名也区分类型参数和值参数：`template <queue_c Queue, DrainDirection direction = from_front>` 中，`Queue` 使用类型参数淡紫 `#B8A9FF`，`direction` 使用值参数杏橙 `#FFC28C`，分别区别于普通类的黄色和变量的珊瑚红；`queue_c` 为薄荷绿，`DrainDirection` 为枚举柔玫粉，`from_front` 为荧光绿。命名头与 concept 补色共用一次转到定义查询，确认为 concept 后为类型参数补色，确认为普通类型后为值参数补色；不凭名字大小写或 `_c` 后缀判断。`typename T`、`class T`、内置类型和 `auto` 等明确参数直接按语法识别，函数指针等复杂声明保持原生配色。此补充只覆盖模板签名中的参数名，引用继续由语言服务处理；它沿用稳定范围、版本缓存和查询限流，可独立用 `dark2026OneDarkPro.cppTemplateParameterHighlighting` 关闭。服务提供原生 `typeParameter` 分类时接管类型参数；值参数继续单独补色，避免与普通函数参数混色。两类模板参数的光晕也独立统计频次，基础强度分别为 0.40 和 0.28。

从仓库根目录执行 `python scripts/install.py --plugin dark2026-one-dark-pro`。安装后按 `Ctrl+K Ctrl+T`，选择 **Dark 2026 + One Dark Pro**。

支持 VS Code `1.111.0` 及以上的 1.x 版本，包括原先支持的 `1.123.0` 及后续版本。主题配色已随扩展打包，安装时无需 VS Code 内置 Dark 2026；源主题所在的 VS Code 版本不等于扩展的最低运行版本。`1.2.7` 将误设的 `^1.123.0` 扩展为 `^1.111.0`，保留原有配色、光晕和 C++ 着色实现。

启用 Synthwave 后，自定义标题栏左上角的 VS Code 图标替换为随包提供的紫蓝霓虹图标，附带柔和光晕；切换主题或停用 Synthwave 后恢复。图标保留原生菜单行为，全屏时沿用原生隐藏规则。使用系统原生标题栏时，其图标由系统绘制，不应用此效果。图片由用户提供，来源为 [Icons8](https://icons8.com/icons/set/visual-studio-code)，保存在 `media/vscode-neon.png`，加载入口内嵌图片数据，无需单独登记路径。

启用 Synthwave 后，VS Code 原生主按钮统一使用紫 → 蓝 → 青的渐变边框、深色渐变底和柔和光晕，包括源码管理的提交与同步、右下角通知、设置及欢迎页中的主按钮；次要按钮保留原有层级。悬停或键盘聚焦时流光在 300 毫秒内移动，分体按钮共用连续渐变。调试底栏使用同一组渐变，顶部有细流光，底色以 6 秒周期缓慢往返。系统启用减少动态效果时保留渐变并停止动画。渐变需要 Loader，安装更新后也要运行一次启用或更新光晕命令。紫、蓝、青三个颜色均可通过 `workbench.colorCustomizations` 调整，示例见[配色说明](Dark2026-OneDarkPro.md)。

按钮效果覆盖工作台中的原生按钮。扩展 Webview 内自绘的按钮、嵌入网页和系统文件对话框由各自的页面或系统控制。

当前行号也使用同一组紫蓝青渐变字和柔和光晕。渐变沿数字从上到下展开，单个数字也能呈现完整的颜色变化；随光标移动自动切换高亮，无需动画或额外扫描。此效果随 Synthwave 启停，与 UI Effects 的行号光晕同时启用时优先使用这组渐变。

原生标签的选中边缘共用 300 毫秒流光展开、淡入和反向收回动画，覆盖编辑器 Tab、问题／输出／调试控制台／终端等面板、侧栏横向导航、设置页和扩展详情页。编辑器 Tab 沿用粉青；面板为紫蓝青、侧栏为薄荷青蓝、设置页为琥珀珊瑚紫、扩展页为蓝紫粉。键盘焦点有独立霓虹标记，减少动画设置下立即切换。编辑区光标、选区、当前行、语法与行号的配色保持现有设置。更新主题后运行 **Dark 2026: 启用或更新 Synthwave 光晕** 生效。

调整分屏、侧栏和面板大小时，分隔条以 300 毫秒 `ease` 动画展开并淡入：竖条从上到下，横条从左到右；离开时反向收回并淡出，完整消失同为 300 毫秒。快速移入移出时从当前状态平滑反向，拖动时保持展开；系统或 VS Code 启用减少动态效果时立即切换。紫蓝青渐变与柔和光晕随指示条一起显示，拖动范围沿用 VS Code 原生设置。原生计数、文字和图标徽标也统一使用同一组渐变，配深色文字及柔和光晕，覆盖 SCM、搜索结果、快速选择框、活动栏、筛选器、操作菜单、配置文件、欢迎页及扩展图标等位置。徽标形状、尺寸、计数、隐藏逻辑与进度动画沿用各原生组件。

SCM 更改统计卡片与源代码管理“图表”的提交悬停卡片统一为 13px 字体、紧凑留白、8px 圆角、深色渐变底与紫蓝青边框，并共用柔和光晕和分隔线。新增与删除分别使用薄荷绿和珊瑚红；图表的分支线、本地/远端标签也采用霓虹色。更新主题后，分别运行 **更改统计: 启用原生悬停** 和 **Dark 2026: 启用或更新 Synthwave 光晕**，再按提示重载。

光晕通过命令 **Dark 2026: 启用或更新 Synthwave 光晕** 注册到 Custom CSS and JS Loader，按提示重新加载即可；无需手写 `media/` 或扩展版本路径。切换到其他主题后光晕自动关闭，切回时恢复。运行 **Dark 2026: 停用 Synthwave 光晕** 可以移除注册；卸载前先停用。

光晕颜色跟随文字，强度按 One Dark Pro 的配色语义组分级：变量、标点和注释较弱，函数、命名空间和关键字居中，类、类型、concept 和枚举较强。命名空间与函数的基础强度均为 0.52，concept 为 0.78，分别按各自的出现频次调整。默认还根据当前可见代码的出现频次调整，越常见越弱。可通过 `dark2026OneDarkPro.glowIntensity` 调整总强度，或用 `dark2026OneDarkPro.frequencyAware` 关闭频次调整；修改后再运行启用或更新命令。同色的语法类型共用一个组，具体算法见完整说明。

标签页底部的粉青渐变共用一组 300 毫秒 `ease` 过渡，比原先的 1 秒更快：选中时从左向右展开并淡入，取消选中时沿相反方向收回并淡出，左粉右青的配色固定。保留 Git 原版的 `ease` 缓动曲线；快速切换时从当前状态平滑反向。底部淡光同步过渡，顶部蓝线已移除。系统启用减少动态效果时立即切换。顶部边线在主题配色中也设为透明，基础主题无需 Loader 即可去除蓝线。

光标变色和拖尾由独立的 UI Effects 插件提供。若只有代码光晕和标签页效果，请运行 **Customize Imports: 启用或更新界面特效** 并按提示重载；主题的光晕命令只登记主题资源。对应插件说明见 [UI Effects](../vscode-ui-effects/README.md)。

生成配色与打包分为两个步骤。在本目录执行：

```powershell
# 仅在需要同步本机源主题时重新生成配色
python scripts/build_theme.py

# 打包已有主题和特效资源
python ../scripts/package_vsix.py .
```

安装产物为 `dist/dark2026-one-dark-pro-1.2.27.vsix`。直接打包和安装不要求本机有 One Dark Pro 扩展；重新生成配色时才需要。

`1.2.27` 扩展 concept 补色到函数体、`requires`、concept 表达式和受约束 `auto`，修复 `if constexpr (deque_c<Queue>)` 仍为通用类型黄的问题。枚举成员改为荧光绿 `#7CFF6B`，模板类型参数与值参数分别使用淡紫 `#B8A9FF` 和杏橙 `#FFC28C`，同步语法、语义配色和光晕分组。

`1.2.26` 将命名空间由 `#7DA9C7` 提亮为雾蓝 `#9BBDE0`，保留命名空间光晕强度；补充模板签名中类型参数与值参数的区分。枚举类型名仍为柔玫粉 `#DCA3C9`，编辑区光标与行高亮配色不变。

`1.2.24` 修复 cpptools 通用类型分类覆盖枚举类型名颜色的问题，补充枚举类型声明与同文件符号引用的前景色；普通类名和关键字保持原色，并保留无清空闪烁的编辑位移与异步刷新行为。

`1.2.23` 将枚举声明和编译期关键字恢复为 One Dark Pro 紫色，保留枚举类型名浅蓝、普通类名黄及枚举成员浅黄绿的区分。

`1.2.22` 根据真实 C++ 模板、concept、枚举及实现代码调整自定义色板：枚举成员改为浅黄绿、编译期关键字改为淡紫，枚举类型改为更柔和的浅蓝；宏保留橙色，One Dark Pro 原色保持不变。同步光晕分组，兼容内置及 Better C++ 的 `static_assert` 分类，并保留 concept 稳定性修复。

`1.2.21` 优先使用语言服务原生 concept 分类，并修复 cpptools 补充着色在编辑时先清空后恢复的问题；保留已确认范围、跟踪编辑位移、合并异步更新，并避免相同范围重绘。

`1.2.20` 区分 C++ 枚举成员、基础类型与文字运算符，并将枚举类型及声明关键字与普通类分色；同时覆盖语法与语义高亮，保留其他语言原有配色。

`1.2.19` 合并多区域导航流光与标题栏霓虹图标，并保留原生界面首帧后启动特效的更新。

特效在原生编辑器界面完成首帧绘制后加载，代码光晕只扫描 Monaco 的内联配色表。安装或更新后，执行一次启用或更新光晕命令，使当前特效资源和共用注入器生效。

Concept 补充着色只查询可见的模板约束、模板表达式和受约束 `auto` 候选，每次最多 64 个、全局最多 4 个并发请求，变化后防抖 250 毫秒。文本分析与定义结果都有缓存，不扫描整个项目。滚动回已确认位置不需要重新着色；编辑时跟踪仍有效的引用与定义范围，后台重新确认。符号尚未被语言服务索引时，等待后续编辑器或诊断更新再重试。开发验证可在本目录运行 `npm test` 和 `npm run check`。

若旧版本出现 `Cannot load 'vscode-userdata:…/synthwave84.js'. Skipping.`，更新安装后先重新加载 VS Code，再执行一次启用或更新光晕命令。插件会把旧导入替换为 Loader 可读取的 `file:` 地址，按提示再次重载即可。
